# Screen sync

Screen sync reads a selected window through Windows Graphics Capture. It estimates damage from health and optional shield decreases, and detects personal kill-feed entries or a kill confirmation badge you teach it. It does not read game memory, inject code, automate input, or use Overwolf. This is experimental and is not approved or certified by Riot.

## Setup

1. Run the game in a window or borderless mode. Use SDR first. Connect your device in HapticBridge.
2. Open **Screen sync**, choose the game window, then **Start preview**. This does not enable vibrations.
3. Open **Calibration**. Select **Health**, press **Freeze**, and drag a rectangle around just the health digits. Leave enough width for all three digits. Enter the number visible in that frame and press **Learn digits** if recognition is incorrect. The match readout should show the correct health value.
4. For kills, select **Use kill feed instead of badges**. This reads gold-outlined personal killer entries in the top-right feed, without learning each weapon skin. Check new kills in the event history. If your HUD does not show those outlines, leave this off and use **Kill badge** and **Learn kill badge** instead.
5. **Save calibration**, then **Resume preview**. Choose the motors and event strengths. Select **Enable output**. Feedback continues while the game is in the background, including when you Alt+Tab.

You can also set the selected region using **Region coordinates**, measured as percentages of the captured window. **Save calibration** keeps the current setup on this computer. Changing resolution, window borders, UI scale or badge cosmetics may require recalibration. Learn more digits from other health values when needed; built-in font templates cover digits you have not taught it.

Kill-feed mode currently targets the standard SDR layout with gold personal outlines and green/red team colors. It ignores rows already visible when preview starts and tracks moving/fading rows to avoid repeats. Other HUD layouts, colors and overlays need verification. It uses one kill source at a time to avoid counting both the feed and badge. Distinct rapid kills can retrigger the reward without waiting for the damage cooldown. Kills confirmed together produce a combined pattern with a separate full-strength peak for each kill; death feedback still takes priority.

Kill badges vary with weapon skins and animations. If one kill appearance is missed while another works, learn the missed appearance too rather than replacing the existing one. Learn a stable, clearly visible appearance for each one you use; **Learn kill badge** retains up to eight appearances. Keep the same badge region while adding them. Changing that region clears the learned badges. **More → Clear learned badges** starts a new set, and **Undo** restores the previous set. Newly exported setups use format version 5; this app still opens version 1 through 4 setups, but older app versions cannot open the new exports. This does not provide automatic recognition of every skin.

For deaths where the health number disappears before reaching zero, freeze a death frame, select **Death text**, and tightly select **KILLED YOU** on the right. Press **Learn death text**, then **Save calibration**. The detector searches vertically as the combat report changes height. It requires three text matches following recent positive health and recent absence of the marker. An old report remaining open does not trigger another death. **More → Clear death text** removes it; Undo restores it. In Deathmatch, select the fixed **RESPAWNING IN** words instead, excluding the changing countdown. The matcher isolates white text from the red banner. This is optional and off in existing setups. Relearn this text after changing resolution or HUD scale; the small letters do not reliably match across sizes. Newly learned templates remember the image dimensions and show **Death text relearn for…** when the preview size differs. Older templates have no size information, and HUD scale changes at the same resolution still need a manual check. Preview both live and dead frames before enabling output.

To stop feedback while spectating, freeze a spectator frame, select **Spectator marker**, and draw a tight rectangle around the **Switch player** prompt (or the equivalent in your language). Press **Learn spectator marker**, then **Save calibration**. Learning activates this optional check; old setups leave it off. Preview the match during spectating and your own play before relying on it. Three consecutive matches stop the motors while keeping Screen sync enabled; suspected marker frames do not start new cues. Feedback resumes after three readable positive-health frames without the marker. It cannot initially be enabled while the marker visibly matches. **More → Clear spectator marker** removes the check; Undo restores it. Moving its region clears its template. Overlays, changed text and layout differences can hide or confuse the marker, so this is not guaranteed player identification.

For shield damage, turn on **Read shield damage** in Calibration, choose **Shield**, then freeze and select only its current 0–50 number. Exclude the shield outline and regeneration reserve; leave room for two digits. Enter the visible number and use **Learn digits** if needed. Check the readout after armor changes, including the dim zero when depleted, then **Save calibration**. Shield reading is off by default; changing it disarms output. An unreadable or absent number is unknown, not zero, so health detection continues but some shield breaks may be missed.

Depleted armor can display a dim zero. When normal shield matching fails, the reader tries local contrast within the selected digit region, retaining its usual shape-confidence checks. Keep the region tight around the number. Flat or weak-contrast crops remain unknown. You can also learn a dim shield digit; health uses separate contrast and local-background fallbacks for bright effects. These retain shape-confidence checks and can still miss obscured digits.

**Undo calibration** restores a changed region, learned digits or badge, including after Reset. It keeps the last 20 edits until the app closes. Press **Save calibration** after undoing to keep the restored setup. Feedback strengths are unchanged.

To calibrate from a screenshot, use **Calibration → More → Open HUD image** and choose a PNG, JPEG or BMP. Capture and output stop, and the image opens frozen for region selection and learning. Use a full-window screenshot at your game resolution. The image stays in memory and is not copied into saved setups; only learned templates and regions are saved. Start a live preview again before enabling output.

Under **Calibration → More**, **Save setup** exports a `.hud.json` file; **Open setup** loads one. Use separate files for different HUD layouts or move a setup to another computer. Files contain recognition regions, learned templates and the shield-reading choice, without motor assignments or strengths. Opening stops output and replaces calibration as one undoable edit. Check the preview, then **Save calibration** to keep it across launches. Loading never starts capture or output. These files contain your calibration data; keep them out of public bug reports.

## Feedback

- **Damage:** a brief pulse on confirmed health or enabled shield loss, stronger at lower remaining health. The slider sets its maximum. Simultaneously confirmed losses become one event; shield regeneration produces no event.
- **Kill:** a short lead-in followed by a peak at the selected strength. Simultaneous kills add a separate peak per kill, up to six.
- **Death:** a brief pulse when zero health is confirmed, or calibrated death text appears as your health HUD disappears. Feedback then waits for respawn and resumes automatically when your live HUD returns.

Each event and motor supports native levels 0–20. Zero disables that event or motor. Motor maximums apply to every event. Each motor has a 450 ms cooldown: death takes priority over kills, and kills over damage. A higher-priority cue can replace a lower-priority one. Distinct kills can retrigger during cooldown; repeated damage and lower-priority cues are skipped. Events assigned to different motors can play together. Muted or unassigned events do not consume a cooldown. Rapid badges that never disappear may count as one kill. Damage lasts 220 ms, death 350 ms, and a single kill 450 ms. Combined kills last up to 1.95 seconds. Delayed device commands do not extend these deadlines.

Under each motor, choose **Damage**, **Kill** and **Death** independently. For example, one motor can follow damage while another handles kills. New motors start with all three choices selected. Changing a choice, strength or maximum turns output off; select **Enable output** again when ready.

Event strengths, motor selection, maximums and event choices save automatically on this computer. They follow the same motor when discovery order changes. Calibration still uses **Save calibration**. Restoring preferences never starts capture or output.

Event history shows **preview**, **muted**, **cooldown**, or how many motors a cue was queued for. **Queued** means playback was requested, not that Bluetooth delivery was confirmed. Cancellation and source or command failures appear separately.

Alt+Tab does not stop capture or feedback. Temporary HUD loss, resizing, death and a recognized spectator marker stop current motor output without turning Screen sync off. It resumes after three readable positive-health frames without a spectator or death marker. Changing the source, losing a selected device, a capture failure, or a device-command failure still disables output. **Stop capture** releases capture; **Stop all** also stops the other output sources. Escape invokes Stop all while HapticBridge has focus, not while the game has focus.

**Stopping output** means a device stop is still pending. **Output stop unconfirmed** stays visible if that stop fails, even after capture ends or calibration changes. It clears after a successful retry or when that playback is replaced. Stopping capture alone does not confirm that the device has stopped.

To stop without switching windows, opt into **Settings → Global Stop all** and choose an unused shortcut. The status must say **Active**. This uses a Windows-registered shortcut, with no game hook or input injection, and stops all sources rather than toggling output. The setting is off by default. Registration and stopping logic have offline test coverage; delivery during actual gameplay remains unverified.

For an optional enable shortcut, open **Settings → Enable Screen sync shortcut**. It is off by default; its suggested binding is **Ctrl + Shift + F9**. After enabling the shortcut, press it in the captured window with a live preview and readable positive health. It enables feedback without switching apps or sending a test pulse. Pressing it while already enabled does nothing. It never starts capture: after **Stop all** or **Stop capture**, start a preview again first. Focus changes, Stop all, shortcut changes or a reconnect cancel a pending enable. A new connection requires another explicit enable.

## Recognition limits

The event preview reports matches, not authoritative game events. Use it before enabling output. Three identical health readings confirm a loss or an initial baseline. Once health is known, three gradually rising readings can update the healing baseline without waiting for healing to stop. Unknown frames break an unconfirmed healing trend. Two badge matches after a cleared interval confirm a new kill. For rapid kills without a full clear, the detector requires a deep visibility drop, two rebuilding frames and three strong matches within a short window. A brief disappearance that returns directly to the same badge does not count again. Some animations can still be missed or mistaken for a restart.

Kill-feed output also requires readable positive health; detecting a feed row alone does not enable feedback. Unreadable health for over one second stops current motor output and waits for a readable HUD. Bright effects can cause this even when the feed remains visible. Recovery is automatic; **Disable output** and **Stop all** stay off until you explicitly enable again.

Health loss from abilities or decay can resemble damage. Hits absorbed without changing health require shield reading and readable shield digits. Health loss and shield changes normally repeat across three frames. When both fall together, three consecutive non-increasing readings can confirm a rapid burst even if the numbers change between hits. Zero health still requires three identical readings; a shield baseline is discarded when that number becomes unreadable, preventing a false hit on reacquisition. Spectating and replay HUDs may resemble your own HUD: keep output off in those modes. A disappearing death HUD may produce signal loss instead of a death cue. Background effects, overlays, compressed video, HDR, font changes and animated badges can cause missed or incorrect detections.

Native Windows capture, calibration, damage and kill previews were tested against a synthetic HUD. Automated tests cover event filtering, multiple simulated motors, delayed commands, source cancellation and stop retries. Real VALORANT match accuracy, latency under game load, and ARM64 capture remain unverified.

## Implementation references

- [OpenCV: Otsu thresholding](https://docs.opencv.org/4.5.5/d7/d4d/tutorial_py_thresholding.html). The health and shield contrast fallbacks use a local luminance histogram and add no OpenCV runtime dependency.
- [Microsoft: Windows screen capture](https://learn.microsoft.com/en-us/windows/apps/develop/media-authoring-processing/screen-capture) and [window capture interop](https://learn.microsoft.com/en-us/windows/win32/api/windows.graphics.capture.interop/nf-windows-graphics-capture-interop-igraphicscaptureiteminterop-createforwindow).
- [Microsoft: RegisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey). Both shortcut actions use separate application ID ranges and suppress keyboard auto-repeat. Conflicting bindings keep the existing working shortcut.
- [Riot: VALORANT developer policies](https://developer.riotgames.com/docs/valorant). Avoiding game hooks is an implementation choice, not a guarantee of approval or exemption from product-registration rules.
- [Riot: Regen Shield introduction](https://playvalorant.com/en-gb/news/game-updates/valorant-patch-notes-9-10/). Its damage absorption can leave health unchanged, which is why shield reading is available separately.
- [Microsoft: Windows OCR](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr). That API's desktop support requires package identity. This unpackaged single-executable app instead uses local digit templates and a user-calibrated badge, with no cloud recognition service.
