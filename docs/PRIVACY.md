# Local data and connections

HapticBridge has no account system or application telemetry service. Device discovery and the native integration API run on this computer. The API binds to IPv4 loopback and authenticates every request with a randomly generated local token. It does not listen on the local network and rejects browser-origin requests.

The app stores its settings, connection file, diagnostic status, activity log and saved patterns below `%LOCALAPPDATA%\HapticBridge`. These files can contain Bluetooth device identifiers, model names, firmware details and application activity. Older mixer presets can contain motor identifiers. The API connection file contains a control credential. Treat this directory and copied API connection JSON as private; a local process that can read the token can control the API while integrations are enabled.

Pattern edits save one local `studio-draft.mix.json` for recovery. It contains numbered curves, links, levels and timing, without device names or identifiers. Recovery is explicit and never starts output. Drafts and manually saved mixes are excluded from public builds.

Screen feedback choices save separately in `screen-feedback.json`. It stores event strengths, selections, maximums and event assignments using hashes of local motor identifiers. These hashes allow matching across launches; they are not anonymous data. The file contains no device names, raw addresses, window details or output-enabled state. It is private local data and excluded from public builds.

Sound sync analyzes the selected Windows audio output in memory. It does not record audio to disk or use the microphone. Audio endpoint identifiers remain in memory and are not exported in mixes. Changing or refreshing the output stops sound sync; start it again deliberately. If Windows changes its default output, restart sound sync to follow the new default.

Screen sync captures only the window you select after **Start preview**. Frames and the short event history stay in memory; no screenshots, window titles or recognition results are uploaded or logged by this feature. Windows displays its capture indicator. **Freeze** holds the preview while capture continues; **Stop capture** or **Stop all** releases it. Saved `screen-profile.json` contains region coordinates, small binary glyph/badge templates and event strengths. It contains no full frames, device identities or window titles, but remains private local calibration data and should not be published. Capture and output are off at startup.

Explicitly exported `.hud.json` setups contain only format metadata, recognition regions, binary digit/badge templates and the shield-reading choice. They exclude event strengths, motor assignments, window identity and full frames. They remain private calibration files; the repository ignore rules and release privacy check exclude them and their temporary save files.

FeelConnect support communicates with `api.feel-app.com` for pairing and session metadata, `fec.feelme.com` for current control messages, and `ps.pndsn.com` for legacy PubNub messages and presence. FeelConnect receives pairing credentials, online/offline presence and device display names supplied by the app. PubNub receives the session's authorized channel names, a random session identifier, and receiver capability/presence metadata. Those services' own privacy terms apply. The legacy receiver uses a public subscribe routing identifier and no publish, partner or secret key; it does not publish actuator commands, request history or discover unrelated channels.

Pairing links and QR codes are credentials: do not post them in bug reports. Pairing tokens and session details stay in memory. During an active session, the app can reuse its in-memory pairing credential to renew the live connection token. HapticBridge does not provide a private relay or an account for these services. The integration follows control messages, rather than downloading or analyzing the video itself. A disconnected or expired session does not automatically reconnect or resume output.

Release builds contain program code, generic capability metadata, documentation and dependency notices. They do not include a developer's connection token, paired-device inventory, saved presets, session logs or browsing material. A new installation generates its own local API token. Downloading the executable does not copy another installation's state.

Before sharing a diagnostic file or preset, inspect it and remove device identifiers and credentials. Do not upload the local data folder to an issue or public repository. To reset local state, close the app and remove its local data folder; this also removes saved patterns and invalidates existing API clients' tokens.
